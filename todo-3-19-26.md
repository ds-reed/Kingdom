Status update as of 2026-04-03

Completed
- Verbs/executor now use `CommandOutcome` end-to-end.
- Executor enforces the contract strictly; legacy string-return bridge is removed.
- Interpreter resolves nouns for both direct objects and prepositional / indirect-object targets.
- `CommandOutcome` messages are processed through text normalization unless explicitly marked as already rendered (`RAW`).
- Text normalization pipeline is in place and exercised by tests:
    - article insertion / definitizing in targeted contexts
    - duplicate-article stripping
    - `..` -> `.` and `....+` -> `...`
    - sentence casing
    - bullet capitalization
    - trailing punctuation cleanup
    - specific false-positive guards for room prose, infinitives, direction bullets, continuation lines, and refusal phrasing
- `spawn_item_to_room` / `_spawn_room_item` updates the lexicon for newly spawned items.
- Guard/container synonym resolution regression is fixed and covered by tests.
- Victrola transport regression is fixed and covered by tests.
- Debug noun resolution now prefers current-room / inventory context and reports ambiguity instead of silently picking an arbitrary global match.
- Concise room rendering now applies bullet capitalization and article insertion, and includes transparent-container context (`held by ...`).
- Prompt styling path has been unified for clone / quit confirmations by routing confirmations through the standard UI prompt flow.

Partial / in progress
- Support duplicate handles / multiple noun matches:
    - noun registry now stores multiple matches intentionally
    - some command paths have been audited to avoid assuming scalar room/noun lookup
    - more audit may still be needed in older utility / special-handler paths
- Support presence in multiple rooms for noun items:
    - some puzzle-specific behavior exists
    - no clean general-purpose model yet
- Parser/interpreter separation:
    - interpreter-side contextual noun resolution is working
    - parser is still doing more resolution work than the eventual target design
- Text normalization stretch goals:
    - redundancy cleanup / sentence rewriting is still not implemented
    - heuristics are intentionally conservative and still need real-play coverage over time

Open
- Overloaded verbs (like `drop` and `look`) should be separated and should use helper functions for overlapping behavior.
- Lexicon update API could still be cleaned up:
    - support a clearer `item=Item, update=True` path if desired
    - continue improving alias-aware lookup helpers across item / room / container APIs
- Create a dedicated portal class for doors / trapdoors / hatches.
- Support random encounters:
    - likely needs a dedicated NPC / encounter model
    - encounter probabilities should account for room/light state
- More safety checks to avoid crashes.

Long-term
- World builder.
- Enrich available `special_handler` behavior functions.
- Mini-game launch support.
